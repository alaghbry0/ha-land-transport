This is a pure-SDK Flutter application — adaptive Material 3 UI, zero third-party dependencies, engineered to be previewed interactively from AI-agent sandboxes. Prioritize the zero-dependency promise and analyzer cleanliness over convenience.

## Project overview

`flutter-sandbox-template` is a Flutter 3.47 stable (Dart 3.13) template engineered to run interactively inside AI-agent sandbox environments (like Z.ai Code sandboxes), where the only user-visible port is served through a reverse-proxy gateway. In the sandbox it is previewed as a debug web build served statically under `/flutter/` by the gateway-hub on port 3000; on a local machine it is a normal Flutter app with full sub-second hot reload on web, Android and iOS. The sibling React Native template is `rn-expo-sandbox-template`. The template makes two hard promises: **zero third-party runtime dependencies** and **`flutter analyze` passing with zero issues**.

## Ground rules for AI agents

- **ALWAYS run `flutter analyze` before committing** — it must report zero issues. If your change produces any analyzer output, fix it before the commit.
- **Never commit `build/` or `.dart_tool/`** — build output is ~48 MB, reproducible from source and regenerated by `scripts/build-web.sh`.
- **Never edit files under `android/` or `ios/`** unless a platform-specific change is the task itself — they are the standard runner projects generated by `flutter create`.
- **Keep ZERO third-party runtime dependencies.** `pubspec.yaml` must stay at `flutter` + `cupertino_icons` (+ `flutter_lints` as a dev dependency). Ask before adding any pub package — the template's promise is pure-SDK.
- **Arabic/English docs must stay in sync** — when you change behavior described in `README.md` (English body + قسم العربية) or in this file, update both languages in the same commit.

## Commands cheat-sheet

```bash
flutter pub get                  # resolve SDK deps — instant, nothing beyond the SDK to fetch
flutter analyze                  # static analysis — MUST be zero issues before any commit
bash scripts/build-web.sh        # incremental debug web build → build/web (~15–45 s)
node scripts/static-server.mjs   # serve build/web on PORT (env var, default 3000)
flutter run                      # local device/emulator — full sub-second hot reload
flutter test                     # runs the test runner (see note below)
```

The template intentionally ships **no tests** — agents working in the sandbox do not write tests unless the user asks for them.

## The sandbox environment (Z.ai)

- **Port 3000 is the only user-visible port** — the outer Caddy gateway forwards the user's preview to it. In this template's live setup, port 3000 is owned by the Node **gateway-hub**, which serves `/flutter/*` statically from `build/web` and proxies everything else (including WebSocket upgrades) to the RN template's Expo server on **3001**. The preview panel therefore shows the RN template at `/` and this template at `/flutter/`.
- **The dev loop is: edit → `bash scripts/build-web.sh` → refresh the preview.** There is **NO hot reload through the preview** — the dwds→DDS debug protocol does not survive the proxy chain; that trade-off is documented and accepted. Use `flutter run` locally when you need sub-second hot reload.
- **CRITICAL — the sandbox "reaper" kills every process spawned by a tool command when it ends** (even with `nohup`/`setsid`/`&`, because they remain descendants of the tool shell). The ONLY reliable escape is the **double-fork pattern** (the process gets orphaned → reparented to PID 1 → outside the reaper's tree):
  ```bash
  ( setsid nohup bash -c 'cd /home/z/flutter-template; exec node scripts/static-server.mjs' >/dev/null 2>&1 </dev/null & )
  ```
  Verify survival with `ps -o pid,ppid,cmd -p <pid>` (PPID must be 1). Use this exact pattern for any server started mid-session.
- **Persistence:** only git-committed files survive sandbox reboots — commit source, docs and scripts after every task. The Flutter SDK (2.3–2.5 GB) lives outside git at `/home/z/flutter`; if it is missing, `scripts/bootstrap-flutter.sh` reinstalls it in ~3–4 minutes.
- The inotify watch limit is **8192** — run one file-watching dev server at a time.
- Memory limit: **~4 GB**.

## Publishing (GitHub)

```bash
GITHUB_TOKEN=<token> bash scripts/publish-template.sh --repo <owner>/flutter-sandbox-template --private
```

- The token is read from the `GITHUB_TOKEN` env var **only** — never an argument, never hardcoded, never written to any file.
- The script creates the repository **private by default** (per owner request). First publish gets a fresh `V1` + `v1` history; subsequent publishes are incremental `V{n+1}` + `v{n+1}`.

## Version management

- Commits as `V{n}: summary`; sequential append-only tags `v1`, `v2`, …
- Tags are never moved or deleted. Restore a version with `git checkout v{n} -- .` followed by a new commit and a new tag with a higher number.
